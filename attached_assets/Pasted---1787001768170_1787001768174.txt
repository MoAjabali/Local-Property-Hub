# 📋 وثيقة تحليل مشروع تطبيق إدارة المباني (نظام Offline مع اشتراكات)

---

## 1. نظرة عامة على المشروع

| العنصر | التفاصيل |
| :--- | :--- |
| **اسم التطبيق** | (يُحدد لاحقاً) |
| **النظام الأساسي** | جوال (Android / iOS) |
| **طبيعة التطبيق** | **Offline بالكامل** (لا يتطلب اتصالاً بالإنترنت للاستخدام اليومي، فقط يحتاج اتصال لحظي للتحقق من صحة التوقيت عند الشك) |
| **الفئة المستهدفة** | مالكو المباني والعمائر السكنية في اليمن |
| **نموذج الربح** | اشتراكات (4 خطط) |
| **نظام الدفع** | تحويل بنكي محلي / كاش / كريبتو (خارج التطبيق) |
| **آلية التفعيل** | أكواد تفعيل (Activation Codes) مولدة بتوقيع رقمي |

## 2. خطط الاشتراك (الـ 4 خطط)

يتم تعريفها في كود التطبيق كثوابت ثابتة:

| اسم الخطة | المعرف | المدة المضافة عند التفعيل | ملاحظات |
| :--- | :--- | :--- | :--- |
| شهرية | `MONTHLY` | 30 يوماً | تُضاف إلى تاريخ الانتهاء الحالي |
| ربع سنوية | `QUARTERLY` | 90 يوماً | تُضاف إلى تاريخ الانتهاء الحالي |
| سنوية | `YEARLY` | 365 يوماً | تُضاف إلى تاريخ الانتهاء الحالي |
| مدى الحياة | `LIFETIME` | تاريخ ثابت = `2099-12-31 23:59:59` | لا يُضاف، يُستبدل التاريخ بهذا التاريخ الثابت |

---

## 3. آلية توليد والتحقق من أكواد التفعيل (الأمن)

### أ. توليد المفاتيح (خارج التطبيق - يقوم به صاحب المشروع)

يتم استخدام **`OpenSSL`** (أداة مفتوحة المصدر العالمية) لتوليد زوج المفاتيح:

```bash
# توليد المفتاح الخاص (يُحفظ في مكان آمن جداً)
openssl genpkey -algorithm RSA -out private_key.pem -pkeyopt rsa_keygen_bits:2048

# استخراج المفتاح العام (يُدمج في التطبيق)
openssl rsa -pubout -in private_key.pem -out public_key.pub
```

**الناتج:**
- `private_key.pem` → **مفتاح خاص (سري)**، يبقى مع صاحب المشروع فقط.
- `public_key.pub` → **مفتاح عام (عام)**، يُضعه المبرمج داخل التطبيق (كملف أو كنص ثابت).

### ب. توليد كود التفعيل (يقوم به صاحب المشروع عند تأكيد الدفع)

يُستخدم المفتاح الخاص لتوقيع بيانات الاشتراك وإنشاء كود تفعيل فريد لكل عميل.

**مكونات الكود (مشفر بتوقيع RSA):**
يجب أن يحمل الكود المعلومات التالية مشفرة وموقعة:
- نوع الخطة (شهري، سنوي، ...)
- تاريخ انتهاء الصلاحية (Expiry Date)
- رقم فريد (Nonce) لمنع إعادة استخدام الكود

**صيغة الكود المقترحة (قابلة للقراءة):**  
مثال: `V2V5c2FsYW0uLi4=` (كود مشفر بتنسيق Base64 أو مشابه، ويحتوي على توقيع رقمي)

**أدوات مفتوحة المصدر لتوليد الكود:**

| الأداة | اللغة | الميزة |
| :--- | :--- | :--- |
| `f-license` | Go | CLI جاهز، يدعم RSA، مثالي لسطر الأوامر |
| `licensify` | Dart/Flutter | مثالي لتطبيقات Flutter، يستخدم `Ed25519` |
| `@flowerjunjie/license-manager` | Node.js | متكامل، يدعم RSA و JWT |
| `open-license` | Python | مكتبة بسيطة للتوليد والتحقق |

**يُفضل استخدام `f-license` أو `licensify`** حسب لغة التطبيق.

### ج. التحقق من الكود (داخل التطبيق Offline)

عندما يدخل العميل الكود في التطبيق، يقوم التطبيق بالخطوات التالية:

1. فك تشفير الكود باستخدام **المفتاح العام** المدمج داخل التطبيق.
2. التحقق من **التوقيع الرقمي** للتأكد أن الكود موقّع بالمفتاح الخاص الصحيح (أي أنه صادر عنك أنت).
3. إذا كان التوقيع صحيحاً، يقرأ البيانات:
   - نوع الخطة
   - تاريخ الانتهاء
   - الرقم الفريد
4. يتأكد من أن هذا الرقم الفريد غير موجود في قائمة `used_codes` (لمنع إعادة الاستخدام).
5. إذا اجتاز الفحص، يقوم بإضافة المدة المستحقة إلى تاريخ الانتهاء الحالي ويحفظ الكود في قائمة المستخدمة.

**هذه العملية لا تحتاج إلى إنترنت أبداً، لأن المفتاح العام موجود داخل التطبيق.**

## 4. واجهة الدفع وعرض بيانات التحويل

هذه شاشة تظهر للعميل عند اختياره لخطة وضغطه على "شراء". يجب أن تعرض:

| العنصر | التفاصيل |
| :--- | :--- |
| **اسم المشترك** | يظهر اسم العميل (مأخوذ من مدخلاته أو من رقم الجوال) |
| **رقم المشترك** | رقم فريد يُولّد محلياً أو يُطلب من العميل إدخاله |
| **المبلغ المستحق** | حسب الخطة المختارة |
| **تفاصيل الحساب البنكي** | اسم البنك، رقم الحساب، اسم صاحب الحساب، رمز SWIFT (إن وجد) |
| **حقل رفع الصورة** | لرفع إيصال الحوالة (صورة فقط) |
| **تعليمات** | "قم بتحويل المبلغ إلى الحساب أعلاه، ثم ارفع صورة الإيصال واضغط تأكيد" |

**مهم:**
- الصورة المرفوعة **لا تُخزن** في أي سيرفر أو قاعدة بيانات.
- يمكن أن تُعرض للمستخدم رسالة "تم إرسال طلبك، سيتم إرسال كود التفعيل خلال 24 ساعة".
- أو يمكن إرسال الصورة عبر البريد الإلكتروني لصاحب المشروع (باستخدام مكتبة `mailto:` أو نية الإرسال).
- أو ببساطة يطلب من العميل إرسال الصورة عبر واتساب إلى رقم معين (وهو الحل الأبسط في اليمن).

**الحل العملي الأبسط:** بدلاً من برمجة رفع الصور، يتم عرض رسالة:
> "يرجى تحويل المبلغ إلى الحساب التالي: ... ثم إرسال صورة الإيصال عبر واتساب على الرقم: +967XXXXXXXX، وسنرسل لك كود التفعيل فوراً."

## 5. آلية إرسال كود التفعيل للعميل

عند تأكيد صاحب المشروع للحوالة:
1. يستخدم أداة توليد الأكواد (مثل `f-license`) على جهازه.
2. يدخل بيانات العميل (نوع الخطة، ورقمه الفريد).
3. تضغط الأداة على "توليد" فينتج كود تفعيل فريد.
4. يرسل صاحب المشروع الكود للعميل عبر **واتساب** (أو أي وسيلة تواصل أخرى).
5. العميل ينسخ الكود ويلصقه في التطبيق، فيُفعّل الاشتراك فوراً.

---

## 6. منطق منع التلاعب بالوقت (Anti-Tamper)

نظراً لأن التطبيق يعمل Offline، قد يحاول المستخدم تغيير تاريخ الجهاز لتمديد الاشتراك. يجب تطبيق الآلية التالية:

**يُخزّن محلياً:**
- `first_install_date` (تاريخ أول تشغيل)
- `last_open_date` (تاريخ آخر فتح للتطبيق)

**عند كل فتح للتطبيق (OnCreate / OnResume):**

```dart
current_time = الآن (من جهاز المستخدم)

if (current_time < last_open_date) {
    // تم الرجوع بالوقت
    showDialog("تم اكتشاف تغيير في وقت الجهاز. الرجاء ضبط الوقت تلقائياً.");
    قفل التطبيق;
}
else if (current_time < first_install_date) {
    // تم الرجوع بالوقت لما قبل التثبيت
    showDialog("تاريخ الجهاز غير صحيح. الرجاء ضبط الوقت التلقائي.");
    قفل التطبيق;
}
else {
    // كل شيء سليم
    last_open_date = current_time;
    // استمر في فتح التطبيق
}
```

**تحسين (اختياري):**  
إذا كان هناك اتصال بالإنترنت لحظة الفتح، يمكن عمل طلب خفيف إلى `https://www.google.com` أو استخدام `NTP` (بروتوكول وقت الشبكة) للحصول على التوقيت العالمي الصحيح ومقارنته بتوقيت الجهاز. إذا كان الفرق أكبر من دقيقتين، يتم قفل التطبيق وطلب تصحيح الوقت.

## 7. تخزين البيانات محلياً

يُستخدم `SharedPreferences` (أو `SQLite` إذا كانت البيانات كبيرة) لحفظ:

| المفتاح | القيمة |
| :--- | :--- |
| `first_install_date` | عدد الميلي ثانية |
| `last_open_date` | عدد الميلي ثانية |
| `subscription_plan` | نص (MONTHLY, QUARTERLY, YEARLY, LIFETIME, NONE) |
| `expiry_date` | عدد الميلي ثانية (تاريخ الانتهاء) |
| `used_codes` | قائمة نصوص (الأكواد المستخدمة سابقاً) |

---

## 8. تدفق المستخدم (User Flow)

1. **التثبيت الأول**: يسجل `first_install_date` ويفتح التطبيق بدون اشتراك (فترة تجريبية 7 أيام اختيارية أو يطلب اشتراكاً فوراً).
2. **الاستخدام اليومي**:
   - كل فتح: تحقق من `expiry_date` مقابل `current_time`.
   - إذا كان `expiry_date` > `current_time` → التطبيق مفتوح بالكامل.
   - وإلا → تظهر شاشة "انتهى الاشتراك، يرجى التجديد".
3. **الشراء**:
   - يختار الخطة.
   - تظهر شاشة الدفع مع تفاصيل الحساب ورقم المشترك.
   - يدفع ويرسل الإيصال (يدوياً عبر واتساب).
4. **استلام الكود**:
   - ينسخ الكود من واتساب ويلصقه في التطبيق.
   - التطبيق يتحقق من الكود محلياً (باستخدام المفتاح العام).
   - إذا كان صحيحاً، يُحدّث `expiry_date` و`subscription_plan` ويُضيف الكود إلى `used_codes`.
   - تظهر رسالة نجاح ويُفتح التطبيق بالكامل.

| المهمة | الوصف |
| :--- | :--- |

| 8 | اختبار جميع السيناريوهات (كود صحيح، كود خاطئ، كود منتهي، كود مستخدم سابقاً، تغيير الوقت... الخ). |

## 11. الأسئلة المفتاحية التي يجب أن يوضحها المبرمج قبل البدء

1. بأي لغة ستكتب التطبيق؟ (Flutter / Kotlin / Swift / React Native)
2. ما هي المكتبة التي ستستخدمها للتعامل مع التوقيع الرقمي (RSA / Ed25519)؟
3. كيف ستُدمج المفتاح العام في التطبيق بشكل آمن؟ (يفضل تخزينه كـ `String` مشفر ضمن الكود)
4. ما هي الخطة في حال كان التطبيق يستخدم مكتبة `f-license` أو `licensify` (هل ستدمجها مباشرة أم تكتب دالة مخصصة)؟
